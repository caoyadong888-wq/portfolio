LedgerLite

Portfolio demo of an invoicing REST API. The company is Vandelay Industries. The company, the customers, and every amount are fictional. This is a demo. Sandbox tenants are deleted after 60 minutes.

Overview

LedgerLite is a small FastAPI service for accounts receivable: customers, invoices, payments, an event stream that is stored and never sent anywhere, and an aging report. Authentication is a password grant plus a hashed API key. Writes require a scope. The public reader login and the public read-only API key cannot write.

The live process listens on 127.0.0.1:18809 behind the portfolio nginx prefix /portfolio/ledgerlite/. SQLite is the database on that host. DATABASE_URL=postgresql+asyncpg://... is the switch for Postgres; the VPS image does not install that driver.

Problem → Solution → Result

Problem

  • A read-only JSON feed does not show how an API product handles authentication, scopes, pagination, idempotent writes, or conflicting updates.
  • Public demos still have to be safe to leave on the internet: fixed credentials, a body cap, rate limits, and no path that renders one user's data into another user's HTML.

Solution

  • One FastAPI app with JWT access tokens, rotating refresh tokens, API keys, cursor pagination, Idempotency-Key, and If-Match.
  • A shared read-only tenant seeded from a fixed random stream, and a sandbox tenant created per login with quotas and a 60-minute lifetime.
  • OpenAPI served by vendored Swagger UI and ReDoc. Nothing is loaded from a CDN.

Result

  • GET /healthz does not touch the database. GET /readyz runs SELECT 1. GET /metrics is Prometheus text.
  • Reader calls that write return 403 with application/problem+json. Sandbox calls that write return 201 until a quota is hit.
  • pytest covers auth, tenancy, pagination, filters, idempotency, concurrency, invoices, aging, rate limits, problems, the OpenAPI document, an in-process schemathesis pass over GET, migrations, and the seed. The landing page shows the recorded summary from results/test_report.json.

These are capabilities of this demo, not claims about a client engagement.

Features

  • Password grant (reader / reader-demo, sandbox / sandbox-demo) and API key ll_demo_read_0000000000000000.
  • Scopes, including *:read for the reader. Missing scope is 403 /problems/insufficient-scope.
  • Cursor pagination (limit 1–100) and Link headers that include the root path.
  • Idempotency keys on invoice create and payment create, kept for 24 hours.
  • If-Match on customer and draft-invoice updates (428 / 412).
  • Invoice states draft → open → paid and draft|open → void. Tax is ROUND_HALF_UP per line in minor units.
  • Aging buckets current, 1–30, 31–60, 61–90, and 90+, grouped by currency.
  • In-process token buckets: 120/min authenticated, 30/min anonymous, 10/min on POST /v1/auth/token. One uvicorn worker. More than one process should use Redis; this demo does not ship a Redis backend.
  • Body cap 32 KB (413). X-Real-IP is trusted only when the TCP peer is 127.0.0.1.
  • Sandboxes: 25 customers, 50 invoices, 100 payments, 60 minutes, at most 200 alive, cleanup every 5 minutes.

Errors use RFC 9457 application/problem+json. Swagger UI is /docs. ReDoc is /redoc. Both load /openapi.json and the files under /static/vendor/ with the ROOT_PATH prefix when it is set. The password flow token URL is the relative path v1/auth/token.

Deployment notes

  • deploy/ledgerlite.service runs as ec2-user, binds 127.0.0.1:18809, sets ROOT_PATH=/portfolio/ledgerlite and DATA_DIR=/opt/portfolio/ledgerlite/data.
  • ExecStartPre migrates (alembic upgrade head) and seeds only when the tenant table is empty.
  • MemoryMax=150M, NoNewPrivileges, PrivateTmp, ProtectSystem=strict, ProtectHome, ReadWritePaths limited to the data directory.
  • The unit file does not contain a signing key. Set LEDGERLITE_JWT_KEY or let the process create DATA_DIR/jwt.key.
  • Single worker. Rate limits live in process memory.
  • On this demo host the TLS front end does not pass the client address, so the proxy sees one address and the per-IP buckets (anonymous 30/min, token 10/min) act as shared limits for all visitors; per-principal buckets (120/min) are unaffected.
  • ./run.sh migrates, seeds if empty, and starts the same entrypoint.
