PulseBoard — Uptime, Latency & SLO Alerting Demo

A compact status page for uptime, latency percentiles, and error-budget alerts.

What it does

PulseBoard probes services every 30s and stores 7 days of samples in SQLite. It reports latency p50/p95, uptime, and error budget against the SLO. An alert state machine moves pending→firing→resolved and appends each step to a notification log. The same signals are published on a Prometheus-style /metrics endpoint and drawn as a Grafana-style dashboard in inline SVG. The catalog has 4 simulated targets labelled DEMO DATA and 6 real health checks.

Prometheus-style /metrics

# HELP probe_success 1 if the last probe succeeded.
# TYPE probe_success gauge
probe_success{target="payments-api",label="DEMO DATA"} 1
probe_success{target="stackpilot",label="real"} 1
# TYPE probe_latency_seconds histogram
probe_latency_seconds_bucket{target="payments-api",le="0.1"} 118
probe_latency_seconds_sum{target="payments-api"} 9.41
probe_latency_seconds_count{target="payments-api"} 120
# TYPE alerts_firing gauge
alerts_firing{state="pending"} 0
alerts_firing{state="firing"} 0
