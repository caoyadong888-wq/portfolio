Shift Handover Report Auto-Generator

交接班报告自动生成模板

Problem / 问题

Handovers are verbal and inconsistent. The useful facts live in one person's notes, a chat scroll, and two exports that nobody lines up. Open P1s and uncleared alarms get lost between shifts.

交接靠口头，每次写法也不一样。有用的事实散在笔记、聊天记录和两份没人对过的导出里。未关闭的 P1 和还没清除的告警，换班时会丢。

Approach / 做法

Structured inputs go in. The generator merges them, paints one RAG status for the whole shift, and writes three files. Samples are a synthetic hall only.

结构化输入进去。生成器合并它们，给整班涂一种红黄绿，并写出三份文件。示例机房是合成的。

shift JSON + ticket CSV + alarm CSV + previous report → generator → RAG → MD / HTML / JSON

班次 JSON + 工单 CSV + 告警 CSV + 上一班报告 → 生成器 → 红黄绿 → MD / HTML / JSON

RAG rules / 红黄绿规则

Red wins over amber. Amber wins over green. A red report still lists the amber reasons when they are also true. The clock for an open ticket stops at the shift window end, not at the wall clock of the machine.

红色压过琥珀色，琥珀色压过绿色。红色报告在琥珀色原因也成立时仍会列出它们。未关闭工单的时钟停在班次窗口结束，不用运行机器的当前时间。

Colour / 颜色When / 何时
Red / 异常 Any P1 incident or P1 ticket is still open, or any alarm is critical and not cleared. 仍有未关闭的 P1，或有严重且未清除的告警。
Amber / 注意 Otherwise, any P2 is still open, any open P1 is older than 4 hours, any open P2 is older than 8 hours, or a task is overdue. Exactly 4 hours and exactly 8 hours are not breaches. 否则是未关闭的 P2、P1 超过 4 小时、P2 超过 8 小时，或任务逾期。刚好 4 小时和刚好 8 小时不算超出。
Green / 正常 None of the above. A false checklist item does not by itself change the colour. 以上都没有。检查单某一项没确认，本身不改变颜色。
