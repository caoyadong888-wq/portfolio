KubeHarbor

Helm chart, Kustomize overlays, and Argo CD apps for a FastAPI service, validated offline. This is a demo. The manifests were rendered and validated offline. Nothing is deployed to a cluster, and kind was not run. Vandelay Industries is fictional. The image ghcr.io/OWNER/ledgerlite:0.1.0 is a placeholder and is not claimed to be published. The prod digest is a placeholder sha256.

  • CKV_K8S_35 LedgerLite reads `DATABASE_URL` from the environment, and the postgres:16-alpine image reads `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB` from the environment. The chart only references keys with `secretKeyRef`. It never places a secret value in values or in a rendered Secret.
  • CKV_K8S_40 The API container runs as uid 10001. The postgres:16-alpine image's `postgres` user is uid 70, and the StatefulSet and backup CronJob use that uid so the image can write its data directory. Forcing a uid above 10000 would not match the image's ownership. The check fires only on those Postgres workloads.
  • CKV_K8S_43 Only the prod API image is digest-pinned, and that digest is a documented placeholder (`sha256:deadbeef` repeated). Dev and staging use the tag `0.1.0`. The in-cluster Postgres image is `postgres:16-alpine`. helm-unittest asserts the prod digest. This check cannot be limited to one environment.
  • CKV_K8S_21 The chart sets `metadata.namespace` from `Release.Namespace`. The six committed renders pass `--namespace ledgerlite-<env>`. Checkov's Helm runner calls `helm template` without `--namespace`, so it reports the default namespace. The Kubernetes-framework scan of `rendered/` does not report this check.

Install snippets

These are the commands a cluster would use. They were not run here. There is no live cluster in this demo.

Helm

helm install ledgerlite charts/ledgerlite \
  --namespace ledgerlite-dev --create-namespace \
  -f charts/ledgerlite/values-dev.yaml

Kustomize

kubectl apply -k kustomize/overlays/dev

Argo CD

kubectl apply -f gitops/argocd/project.yaml
kubectl apply -f gitops/argocd/app-of-apps.yaml

Prod automation is disabled in gitops/argocd/app-prod.yaml. Prune and selfHeal stay on. The files are not applied.
